# data/validation — 시설 데이터 검증

정제·적재 전에 원본 좌표가 믿을 만한지 확인한 스크립트와 결과 목록. 담당 상협, 정제(근영)에서 참고용.

- 입력: 근영 원본 수집본 `data/raw/*.csv` (노션 "캡스톤" 3.2의 `raw.zip`, 커밋 안 함)
- Python 3.9+ 표준 라이브러리만 사용 (pandas 불필요)
- 결과 CSV는 팀 공유용으로 커밋한다 (`.gitignore` 예외). 주소 검색 캐시 `.cache/`는 커밋 안 함

## 파일

| 파일 | 내용 |
|---|---|
| `check_address.py` | 비상벨·CCTV·보안등 좌표를 카카오 주소 검색 결과와 전수 대조, 300m 넘게 어긋난 행 저장 |
| `check_precision.py` | 좌표 소수점 자릿수를 구별로 세고 4자리 이하 행 저장 |
| `check_streetlight.py` | 가로등(주소 없음)이 같은 구 보안등 1km 안에 있는지 검사, 출력만 |
| `compare_files.py` | 원본과 가공본 CSV를 ID로 맞춰 빠진 행·바뀐 좌표 확인, 출력만 |
| `common.py` | 데이터셋 정의(원본 컬럼명), CSV 읽기, 거리 계산, 주소 검색 캐시 |
| `address_mismatch.csv` | 주소와 300m 넘게 어긋난 행 541개 |
| `low_precision.csv` | 소수점 4자리 이하로 등록된 행 174개 |

### `address_mismatch.csv` 컬럼

| 컬럼 | 내용 |
|---|---|
| `dataset` | 비상벨 / CCTV / 보안등 |
| `id` | 원본 식별값 — 비상벨 `MNG_NO`, CCTV `manageNo`, 보안등 `LMP_LC_NM`(위치명, 121건 중복이라 주소와 함께 볼 것) |
| `gu` | 구 (비상벨은 자치단체코드, 나머지는 주소·기관명에서 추출) |
| `distance_m` | 원본 좌표 ↔ 주소 검색 좌표 거리(m) |
| `band` | 300m~1km / 1~20km / 20km 이상 |
| `address` | 검색에 쓴 주소 (도로명 우선, 검색 실패 시 지번) |
| `lat`, `lon` | 원본 좌표 |
| `note` | `대전 범위 밖`, `경도 0.0175° 서쪽 밀림` 패턴 표시 |

카카오가 돌려준 좌표는 공개 저장소에 쌓지 않으려고 거리만 남겼다. 필요하면 로컬에서 `check_address.py`를 실행한 뒤 `.cache/geocode_cache.json`에서 주소로 찾는다.

## 실행 방법

```bash
# 1. 노션 "캡스톤" 3.2의 raw.zip을 받아 data/raw/에 푼다 (cctv.csv, emergency_bell.csv, ...)

# 2. API 없이 도는 검사
python3 data/validation/check_precision.py
python3 data/validation/check_streetlight.py
python3 data/validation/compare_files.py --other ~/Downloads   # 가공본 폴더와 비교할 때

# 3. 주소 대조 — 카카오 REST 키 필요
set -a; . ./.env; set +a
python3 data/validation/check_address.py
```

- 주소 대조는 처음 실행할 때 카카오 주소 검색을 약 28,600건 부른다 (일 100,000건 무료, 등대 앱 쿼터 공용). 같은 주소는 한 번만 부르고 `.cache/`에 저장해 두므로 다시 돌리면 새 주소만 부른다
- 분당 약 1,200건 속도라 처음에는 25분쯤 걸린다. 1,000건마다 캐시를 저장해서 중간에 멈춰도 이어서 돈다

## 결과 (2026-10-03, 원본 기준)

### 주소와 300m 넘게 어긋난 행 — 어긋남 / 판정

| 구 | 비상벨 | CCTV | 보안등 |
|---|---:|---:|---:|
| 동구 | **34 / 190 (17.9%)** | 21 / 475 (4.4%) | 92 / 7,015 (1.3%) |
| 중구 | 0 / 156 | 20 / 460 (4.3%) | 69 / 6,139 (1.1%) |
| 서구 | 3 / 65 (4.6%) | **142 / 751 (18.9%)** | 107 / 7,249 (1.5%) |
| 유성구 | 0 / 47 | 30 / 493 (6.1%) | 12 / 3,814 (0.3%) |
| 대덕구 | 1 / 71 (1.4%) | 8 / 536 (1.5%) | 2 / 3,308 (0.1%) |
| **합계** | **38 / 529 (7.2%)** | **221 / 2,715 (8.1%)** | **282 / 27,525 (1.0%)** |
| 20km 이상 | 28 (전부 동구) | 1 (서구) | 0 |
| 판정 못 함 (주소 없음·검색 실패) | 46 | 270 | 1,054 |

- **비상벨 동구**: 20km 이상 어긋난 28행 중 27행이 아래 4자리 행. 나머지 1행(홍도어린이공원)은 경도가 127.12로 대전 밖
- **CCTV 서구**: 94행이 위도는 그대로, **경도만 정확히 0.0175°(약 1.57km) 서쪽으로 밀림** (`note`에 표시). 밀린 양이 0.00001° 안쪽으로 같아 입력·변환 실수로 보인다. 관리번호 속 장소명을 키워드 검색한 표본 20개 중 판정된 9개에서 8개가 주소 쪽이 맞음
- CCTV 서구 20km 이상 1행(정림동성당근처(고정))은 위도 36.607 — 같은 지점 다른 행은 36.307이라 오타
- 보안등은 어긋난 방향이 제각각이라 일정한 패턴 없음
- "어긋남"은 원본 좌표와 주소 중 어느 쪽이 틀렸는지까지는 말해 주지 않는다. 주소가 틀린 경우도 있다 (예: CCTV 모롱이어린이공원은 원본 좌표가 맞음)

### 소수점 자릿수

| 데이터 | 행 수 | 4자리 이하 | 대부분 |
|---|---:|---:|---|
| 비상벨 | 575 | **173** (동구 171, 서구 1, 대덕구 1) | 6~8자리 |
| CCTV | 2,985 | 1 (서구) | 8자리 |
| 보안등 | 28,579 | 0 | 10자리 |
| 가로등 | 43,082 | 0 | 8자리 |

- 4자리 = 위치가 약 10m 단위로만 기록됨. 반올림이면 최대 약 7m, 버림이면 최대 약 14m 어긋난다
- 3자리로 보이는 값은 끝자리 0이 빠진 4자리 (4자리 값의 끝자리에 0이 하나도 없고, 3자리 값 개수가 다른 끝자리 빈도와 비슷)
- 원본부터 4자리라 수집·가공 중 잘린 게 아니다

### 가로등 (주소 없음)

대전 범위 밖 0행. 같은 구 보안등이 1km 안에 없는 가로등은 1,004행(유성구 719, 서구 257, 대덕구 22, 중구 6)이지만 가장 먼 것도 1.6km — 보안등이 드문 큰길로 보이고, 비상벨 같은 20km급 오류는 없다. 수십~수백 m 오차는 이 방법으로 못 잡는다.

### 원본 ↔ 상협이 받은 가공본 (`~/Downloads`)

좌표 값은 4종 모두 원본과 같다 (일부는 끝자리 0 표기만 다름). 가공본에서 빠진 3행: CCTV 완전 중복 1행(대신1길 4거리), 대전 밖 좌표 2행(비상벨 홍도어린이공원 경도 127.12, CCTV 정림동성당근처 위도 36.607).
