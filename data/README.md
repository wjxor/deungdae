# data — 공공데이터 수집·정제 (담당: 정근영)

Python 3.12+ (pandas, GeoPandas) 전처리 노트북·스크립트를 둔다.

- **원본 파일(CSV·XLS 등)은 커밋하지 않는다.** `data/raw/`에 내려받고, 아래 표에 출처와 다운로드 방법만 기록한다
- 좌표계는 전부 WGS84(EPSG:4326)로 변환해 적재한다
- 결측·대전 밖 행은 제거하고 제거 건수를 기록한다
- 원본 좌표 검증 스크립트와 결과 목록(주소와 어긋난 행, 소수점 4자리 행)은 [`validation/`](validation/README.md)

## 원본 수집

공공데이터포털 API로 5종을 받아 `data/raw/`에 CSV로 저장한다. 공공데이터포털 서비스 키가 필요하다.

```bash
# 1. 패키지 설치 — 레포 루트에서 (가상환경 권장)
pip install -r data/requirements.txt

# 2. 루트 .env에 공공데이터포털 서비스 키를 넣는다 (.env.example 참고)
#    DATA_GO_KR_KEY=...

# 3. 수집 — 인자가 없으면 5종 전부, 이름을 주면 그것만
python data/collect_raw_data.py
python data/collect_raw_data.py cctv police

# 4. 건수·중복 검사
python data/check_duplication.py
```

| 파일 | 내용 |
|---|---|
| `collect_raw_data.py` | 5종 원본 수집. 이름: `security_light`(보안등) · `cctv` · `street_light`(가로등) · `emergency_bell`(비상벨) · `police`(지구대·파출소) |
| `check_duplication.py` | 종류별 전체 건수, 완전 중복, ID 중복, 같은 좌표 중복 출력 |
| `clean_facilities.py` | 원본을 `facilities` 형식 CSV로 정제 (아래 "정제") |
| `load_facilities.py` | 정제 CSV를 DB에 적재 (아래 "적재") |
| `bell_final_coords.csv`, `police_coords.csv` | 정제 입력 중 손으로 정한 좌표 (아래 "정제") |
| `requirements.txt` | `requests`, `pandas`, `python-dotenv`, `psycopg[binary]` (적재용) |

- 어느 폴더에서 실행해도 `data/raw/`에 저장하고 거기서 읽는다
- 서비스 키는 인코딩 키·디코딩 키 어느 쪽을 넣어도 된다 (스크립트가 디코딩해서 쓴다)
- API 오류가 나면 상태 코드와 서버 응답 앞부분만 출력한다. 서비스 키가 든 URL은 출력하지 않아서 오류 메시지를 그대로 공유해도 된다
- `raw.zip` 원본으로 `check_duplication.py`를 돌리면 위 원본 건수와 CCTV 같은 좌표 461곳이 그대로 나온다 (docs/HISTORY.md 5주차 "데이터 검증")

## 정제

`data/raw/*.csv`를 ERD의 `facilities` 형식 CSV 5개로 바꾼다. 결과는 `data/processed/`에 저장되고 커밋하지 않는다(`*.csv`는 `.gitignore`). 정제 규칙을 바꾸면 스크립트를 고쳐 다시 돌려서 다시 만든다.

```bash
# 레포 루트에서 — 원본 수집(위)을 마친 뒤
python data/clean_facilities.py
```

출력 열: `type, source_key, name, address, district, lat, lng, coord_source, attributes(JSON)`. `id`·`created_at`·`location`은 DB가 만들고 `data_source_id`는 적재할 때 `data_sources` 행을 만들어 붙인다. 관리번호(안심벨 18자리)는 문자열로 읽으니 CSV를 엑셀로 열어 저장하지 않는다.

### 입력 파일

| 파일 | 내용 | 커밋 |
|---|---|---|
| `data/raw/*.csv` | 수집 원본 | 안 함 |
| `data/bell_final_coords.csv` | 안심벨 575행의 최종 좌표 (`관리번호, 최종_위도, 최종_경도, 최종_좌표_출처`) | 함 |
| `data/police_coords.csv` | 지구대·파출소 31곳 좌표 (`관서명, lat, lng`) | 함 |
| `data/validation/address_mismatch.csv` | 상협의 주소 대조 결과 (CCTV 경도 보정 대상) | 함 |

안심벨 최종 좌표와 지구대·파출소 좌표는 사람이 정한 값이라 스크립트로 다시 만들 수 없어서 커밋한다.

### 정제 결과

| 종류 | 입력 | 저장 | 제외 | 좌표를 고친 행 |
|---|---:|---:|---:|---|
| 가로등 | 43,082 | 43,082 | 0 | 0 |
| 보안등 | 28,579 | 28,579 | 0 | 0 |
| CCTV | 2,985 | 2,984 | 1 (완전 중복) | 95 (`coord_source=corrected`) |
| 안심벨 | 575 | 575 | 0 | 1 (직접 설정) + 변환 29 |
| 지구대·파출소 | 31 | 31 | 0 | 0 (31곳 모두 주소를 변환한 좌표, `geocoded`) |

좌표가 없거나 대전 범위 밖(위도 36.18~36.51, 경도 127.24~127.57, `validation/common.py`의 `DAEJEON_BBOX`와 같음)인 행은 5종 모두 걸러서 제외 건수를 출력한다. 위 표에서 대전 밖으로 빠진 행은 0건이다. 안심벨·CCTV의 대전 밖 좌표는 아래처럼 먼저 고쳤기 때문이다.

### 종류별 규칙

- **보안등**: 설치 개수(`INSTALLATION_CO`)가 1이 아닌 95행이 있어 `attributes.lamp_count`에 넣는다. 가로등은 `fixture_count`
- **CCTV**
  - 완전히 같은 행(관리번호·좌표 동일) 1건은 하나만 남긴다
  - 서구 94건은 위도는 그대로이고 경도만 서쪽으로 약 1.57km 밀려 있어(원본도 같은 값) 경도에 +0.0175를 더한다. 대상은 `address_mismatch.csv`에서 "경도 0.0175° 서쪽 밀림"으로 표시된 서구 94행이다. 보정하면 주소와의 거리가 중앙값 4m·최대 207m로 줄어든다(상협 리뷰에서 확인한 값)
  - 서구 보정 대상 중 주소가 행정동 이름(도마1동·갈마2동·관저2동)인 8행(4곳, 회전·고정 2대씩) 가운데 도로명이 있는 3곳(도학4길 38, 갈마로 147번길 5-8, 갈마중로 28번길 24-8)은 같은 도로명 보안등이 보정한 위치에서 14~16m, 원본 위치에서는 1.5km 넘게 떨어져 있어 보정이 맞다
  - 같은 목록의 동구 `038.(2012-47) 판암초 주변` 1행도 같은 밀림 표시지만 보정하지 않는다. 원본 위치에서 7m에 판암동 328, 20m에 판암동 322-2(CCTV 주소와 같은 번지) 보안등이 있고 판암초교 CCTV와 약 150m 거리이다. +0.0175를 더하면 삼정동(삼정동 302 보안등 8m)이 되어 주소와 맞지 않고 판암초교 CCTV와 1.4km 떨어진다. 주소 검색이 판암1동 번지를 삼정동의 같은 번지로 찾아 어긋난 것으로 보인다. 스크립트의 `LNG_SHIFT_EXCLUDE`에 이유와 함께 적었다
  - `030-1.(200-2011-24) 정림동성당근처(고정)`은 위도가 36.60749673으로 대전 밖이다. 원본에 같은 주소(정림동 13-16)·같은 경도의 `030.(200-2011-24) 정림동성당근처`가 36.30749673이고 숫자 하나(3→6)만 달라서 36.30749673으로 고친다
  - 같은 좌표에 여러 대인 곳(461곳)은 행을 합치지 않고 그대로 둔다
- **안심벨**: 최종 좌표는 `bell_final_coords.csv`. 원본 좌표를 카카오·네이버 주소 검색 결과와 대조해서 정했다
  - 원본 유지 545행: 주소 검색 좌표와 거의 같다(대부분 50m 이내). 50m 넘게 어긋난 일부는 지도에서 위치를 확인하고 원본을 유지했다(300m 넘게 어긋난 10행은 아래 "원본을 유지한 안심벨 10행"). 소수점 4자리로 등록된 173행(동구청 171 외 2) 중 146행은 위치 오차가 최대 약 14m라 원본 그대로 쓴다
  - 변환 29행(`geocoded`): 원본이 주소와 1km 넘게(28행은 20km 넘게) 어긋나 장소명과 대조한 뒤 주소 변환 좌표로 바꿨다. 도로명 주소 변환 19행, 지번 주소 변환 10행. 20km 넘게 어긋난 행 대부분(27행)이 위의 4자리 173행에 들어 있다. 그중 1행은 카카오·네이버 검색 결과가 없어 findlatlng.org 변환 좌표가 안전지도의 비상벨 위치와 맞는 것을 확인하고 썼다
  - 직접 설정 1행(`corrected`): 읍내동 5-17(`202436800000900003`). 주소로 위치를 찾을 수 없어서, 원본에 "용화사 앞 화장실 내부"라고 적힌 것을 보고 지도에서 용화사 화장실을 찾아 그 좌표를 넣었다
  - `last_check`는 원본 점검 결과 값(Y 572 / N 3)을 그대로 둔다
- **지구대·파출소**: API에 좌표가 없어 주소를 지도 사이트(findlatlng.org)에서 변환해 `police_coords.csv`에 적었다. 주변 가로등·보안등 위치와 대조해 검증했고, 카카오 주소·키워드 검색과 비교해 어긋난 문화지구대(316m)는 카카오 검색 좌표로 바꿨다
  - `source_key`와 좌표 연결은 `관서명`으로 한다. `연번`은 전국 목록의 순번이라 경찰청이 목록을 갱신하면 바뀔 수 있다. 대전 31곳은 이름이 모두 다르고 스크립트가 이름이 겹치거나 좌표 파일과 다르면 멈춘다
  - 신탄진지구대는 원본 주소(`대덕대로 1427`)가 주소 검색에 나오지 않는다. 키워드 검색으로는 `대덕대로 1472`에 있고 좌표는 맞아서 원본 주소의 오타로 본다(주소는 원본 그대로 둔다)
- 원본 주소의 오타(`유성궁`, `중수`)는 `district`를 뽑을 때만 고쳐서 쓴다

- 이 10행과 정제 후에도 주소와 어긋난 CCTV·보안등 행을 어떻게 할지는 팀 회의 안건이다(ROADMAP "팀에서 정해야 할 것")

## 적재

`data/processed/`의 정제 CSV 5개를 DB의 `facilities` 테이블에 넣는다. 정제(위)를 마친 뒤에 한다.

```bash
# 레포 루트에서
pip install -r data/requirements.txt

# 1. 점검만 - CSV 규칙을 확인하고 DB에는 연결하지 않는다
python data/load_facilities.py

# 2. 연결 확인 - DB에 연결해 facilities, data_sources 건수만 읽는다
python data/load_facilities.py --check-db

# 3. 적재 - 팀과 합의한 뒤 한 번만
python data/load_facilities.py --commit
```

- DB 주소는 루트 `.env`의 `DIRECT_URL`(없으면 `DATABASE_URL`)을 읽는다. 주소와 비밀번호는 화면에 출력하지 않는다
- 종류별로 `data_sources` 행을 만들고(원본 건수, 적재 건수, 출처 주소, 수집일 2026-09-30) 그 `id`를 `facilities.data_source_id`에 넣는다. 위치는 `ST_SetSRID(ST_MakePoint(lng, lat), 4326)::geography`로 경도가 먼저다
- 한 번에 처리해서 하나라도 틀리면 전부 취소한다. `facilities`나 `data_sources`에 이미 데이터가 있으면 중복 적재를 막으려고 멈춘다. 정제 기준이 바뀌어 다시 적재하려면 스크립트를 고쳐야 한다(별도 PR). 안전점수는 요청마다 DB로 다시 세서 `route_cache`(카카오 경로만 저장)는 비우지 않아도 된다
- 적재가 끝나면 모든 점이 대전 범위 안에 있는지 확인한다
