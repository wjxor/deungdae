# 경유지 실험 — A 보강(안심시설 밀집 지점을 경유지로)이 안심경로를 바꾸는가

실험일: 2026-11-04 · 담당: 전승민 · 관련: FR-006, ROADMAP "A 보강"

```bash
(cd apps/api && npm run build)      # 스크립트가 서버의 점수·구간 나누기 코드를 dist에서 그대로 쓴다
# 200쌍. --pairs는 변수에 담지 않고 명령마다 그대로 쓴다 (zsh는 따옴표 없는 변수를 공백에서 나누지 않아 --pairs가 무시되고 기본 60쌍으로 돈다)
node --env-file=.env scripts/waypoint-experiment.mjs baseline   --pairs scripts/route-pairs.json,scripts/route-pairs-score.json,scripts/route-pairs-score-extra.json   # 최단·큰길 기준 경로 (쌍마다 2건, 200쌍 400건. 안전점수 실험 응답이 있으면 그걸 씀)
node --env-file=.env scripts/waypoint-experiment.mjs candidates --pairs scripts/route-pairs.json,scripts/route-pairs-score.json,scripts/route-pairs-score-extra.json --when all --corridor 100   # 경유지 후보를 DB에서 고름 (카카오 안 부름)
node --env-file=.env scripts/waypoint-experiment.mjs route      --pairs scripts/route-pairs.json,scripts/route-pairs-score.json,scripts/route-pairs-score-extra.json --when all --corridor 100   # 경유지를 넣은 경로를 받아 저장 (이때 쓴 카카오 269건)
node --env-file=.env scripts/waypoint-experiment.mjs report     --pairs scripts/route-pairs.json,scripts/route-pairs-score.json,scripts/route-pairs-score-extra.json --when all --corridor 100 --max-retrace 10   # 점수를 매기고 지금 규칙과 비교 (카카오 안 부름)
```

카카오 키는 개인 앱의 REST 키를 `.env.mine`에 두고 `--env-file=.env --env-file=.env.mine`으로 넘겼다. 팀 앱의 하루 1,000건을 쓰지 않으려는 것이다. 응답은 `scripts/output/waypoint/`에 저장돼 다시 부르지 않는다(gitignore). 설정을 바꿔 경유지가 달라지면 새로 부른다.

기준 경로(최단·큰길)는 안전점수 실험이 받아 둔 같은 반올림 응답(`scripts/output/rounded/<쌍 id>/walk-SHORTEST.json`·`walk-BROAD_FIRST.json`)이 있으면 카카오를 부르지 않고 그걸 복사해 쓴다 (2026-11-04 상협 리뷰). 이 문서의 숫자는 따로 받은 기준 경로로 낸 것이라, `rounded`로 돌리면 조금 다를 수 있다 (최단·큰길이 같은 쌍 76 → 75쌍, 지금 큰길만 32쌍은 같음).

스크립트는 우회 한도를 서버 `SAFE_MAX_DETOUR`에서 읽는다. 이 문서의 숫자는 한도가 20%일 때 낸 것이다. 2026-11-04 이 실험을 보고 30%로 바꾼 뒤(PR #53)에 돌리면 고르는 규칙과 아래 경유지 직선 합 상한(1.3배)이 모두 30% 기준이라 숫자가 다르다.

## 목적

안심경로는 지금 B안(최단 + 넓은 길 우선 중 고르기)이다. 두 후보가 같은 길이면 고를 게 없다(200쌍 중 168쌍이 같은 경로로 나옴). 안심시설이 몰린 지점을 경유지로 넣은 후보를 더하면, 실험할 때 서버 규칙(최단보다 5점 이상 높고 우회 20% 이하)에서 안심경로가 다른 길이 되는 쌍이 얼마나 느는지 본다.

## 방법

- **쌍**: `docs/safety-score-experiment.md`의 200쌍 그대로
- **기준 경로**: 쌍마다 최단(`SHORTEST`)과 넓은 길 우선(`BROAD_FIRST`)
- **경유지 후보** (`--when all`): 최단 기준 경유지(`S+경유`)와 큰길 기준 경유지(`B+경유`)를 쌍마다 만들어 후보에 더한다. 카카오는 `route_mode`를 기준과 같게 하고 경유지 좌표를 `via_x`·`via_y`로 넘긴다
- **경유지 고르기**: 아래 값은 모두 임시 실험 값이다. 팀이 정한 값이 아니다
  - 기준 경로(최단·큰길)에서 100m 안(`--corridor`)의 시설을 후보로 본다. 기준 경로 위(60m 안), 출발·도착 150m 안은 뺀다
  - 밀집도는 서버 점수와 같은 방식이다: 후보 지점 반경 30m 안 시설의 가중치 합, 같은 좌표의 CCTV·안심벨은 한 곳, 원점수 상한 10
  - 밀집도가 높은 지점부터 최대 3개(`--max-via`), 서로 300m 이상(`--min-gap`), 밀집도 5 이상(`--min-density`). 출발→경유지들→도착 직선 합이 최단 거리의 1.2배(1 + 우회 한도)를 넘는 조합은 쓰지 않는다
  - 경로를 따라 출발에 가까운 순으로 카카오에 넘긴다
- **되돌아감 탈락** (`--max-retrace 10`): 경유지가 골목·막다른 길에 있으면 카카오가 들어갔다 같은 길로 나오는 경로를 만든다. 경로가 앞서 지나간 자리의 12m 안으로 다시 돌아온 길이(10m 간격 점 × 30m 넘게 앞선 점)가 10m 이상, 곧 하나라도 있으면 후보에서 뺀다. 되돌아감이 0m인 경로만 쓴다
- **채점**: 서버의 구간 나누기·SQL·점수 함수를 그대로 쓴다. 규칙은 `SAFE_MIN_GAIN`(5점)·`SAFE_MAX_DETOUR`(실험 때 20%)

## 결과

200쌍 중 안심경로가 최단과 다른 길인 쌍:

| 후보 | 20% 이하 | 30% 이하 |
|---|---|---|
| 지금 (큰길만) | 32쌍 (16%) | 36쌍 |
| 경유지 추가, 되돌아감 탈락 전 | 53쌍 | 63쌍 |
| **경유지 추가, 되돌아감 0m만** | **41쌍 (20.5%)** | 47쌍 |

- 경유지가 고른 길은 12쌍(우회 20% 이하). 점수 차 중앙값 8점, 우회 중앙값 9%, 추가 거리 중앙값 163m. 지금 큰길이 고르는 쌍은 우회 4%, 87m
- 12쌍 중 지금 "같음"이던 쌍이 9쌍 새로 다른 길이 됐고, 3쌍은 큰길 대신 경유지가 골라졌다. 안심경로로 고른 41쌍 전체의 추가 거리는 중앙값 103m, 최대 413m
- 우회 한도를 30%로 풀면 큰길만 36쌍(+4), 경유지 추가 47쌍(+6)이다. 추가 거리 최대는 413m에서 447m로 거의 같다
- 되돌아감 기준별로는 50m 미만 46쌍, 30m 미만 42쌍, 0m 41쌍이다. 점수 차 중앙값은 모두 8점이고 쌍 수만 준다
- 경유지를 최단=큰길인 76쌍에만 넣으면(`--when same`) 효과가 작았다. 경로 폭 250m에서 +1쌍, 150m에서 +3쌍, 100m에서 +6쌍. 124쌍(이미 다른 길)에서 큰길보다 나은 길을 만드는 쪽이 더 컸다
- 경로 폭을 좁히면 우회가 준다(우회 중앙값 250m 폭 48%, 100m 폭 16%). 대신 5점 이상 오르는 쌍도 준다
- 되돌아감을 보지 않으면 경유지가 29쌍에서 선택되는데, 그중 18쌍이 되돌아감이 있었다(`dong-37` 180m 등). 효과의 절반 이상이 곁가지에 기댄 셈이다

## 한계

1. **평가와 선택이 같은 신호다.** 경유지를 시설 밀집도로 고르고 점수도 시설 밀집도로 매겨서, 점수가 오르는 건 예상된 결과다. 실제로 더 안전한지는 이 실험으로 알 수 없다
2. **설정을 같은 쌍으로 맞췄다.** 경로 폭 100m·밀집 5·되돌아감 0m는 결과를 보며 정했다. 새 쌍에서는 효과가 더 작을 수 있다
3. 늘어난 9쌍은 200쌍의 4.5%로 표본 오차(±5%p대)보다 작다. 방향은 보이지만 우연이 아니라고 단정하기 어렵다
4. 되돌아감 길이는 근사다. 굽은 길을 되돌아감으로 세거나 곁가지를 놓칠 수 있다
5. 큰길 경로의 되돌아감은 보지 않았다
6. 경로 점수는 2026-11-04 전 서버(CCTV·안심벨을 대수로 셈)로 매겼다. 서버가 종류별로 같은 좌표를 한 곳으로 세게 된 뒤(PR #54) 다시 돌리면 점수가 조금 다를 수 있다. 경유지 밀집도는 처음부터 지점으로 셌고, 안전점수 실험 200쌍에서는 지점으로 세도 고르는 길이 바뀌지 않았다

## 호출 비용

지금 검색 한 번은 카카오 2건(최단·큰길)이다. 경유지 후보를 더하면 최대 4건이다. 하루 1,000건이면 검색 가능 횟수가 약 500회에서 약 250회로 준다. 응답 시간(NFR-001, 3초)도 다시 재야 한다. 서버 배포처(ROADMAP)와 캐싱을 먼저 정해야 한다.

## 결론

경유지를 넣으면 안심경로가 다른 길이 되는 쌍이 16%에서 20.5%(41쌍)로 늘고, 늘어난 길은 짧은 우회(중앙값 163m)로 점수를 올린다. 그러나 점수 자체가 시설 밀집도라서 안전하다는 보증은 아니고, 호출이 두 배가 된다. 12주차 1차 배포 뒤에 캐싱과 쓰는 조건을 정하고 넣을지 결정한다 (서버 배포처는 Vercel로 정했다 — 2026-11-11, ROADMAP "결정된 것"). 이 문서의 숫자는 임시 실험 값으로 얻은 것이다.
