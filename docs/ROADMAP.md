  - 등록 위치: 콘솔 개편(2025-12-03) 뒤로는 [앱 설정] > [앱] > [플랫폼 키] > [JavaScript 키] > [JavaScript SDK 도메인]. 옛 [플랫폼] > [Web] > [사이트 도메인]은 없어짐. 키마다 설정이 따로라 도메인을 등록한 키와 `.env`의 `VITE_KAKAO_JS_KEY`가 같은 키여야 한다
  - 나중에 볼 것: REST API 키의 "허용 IP 설정"으로 서버 IP만 허용할 수 있음. 서버리스(Vercel)는 IP가 고정되지 않아 맞지 않을 수 있어 서버 배포처 정할 때 함께 결정

### 안심경로 계산 방식 (FR-006) — B 기본 + A 보강 확정

2026-10-18 상협 확인. 4~7주차 발표자료(승민 작성) 4장의 "B를 기본으로 하고 A로 보강, 추후 시간이 남으면 자체 엔진"과 같다.

| 안 | 방식 | 장점 | 약점 |
|---|---|---|---|
| A 경유지 우회 | 안전시설 밀집 지점을 경유지(최대 5개)로 넣어 카카오 경로를 끌어당김 | 카카오 기본 옵션에 없는 새 길을 만들 수 있음 | 경유지 선정 로직을 직접 설계해야 함. 잘못 잡으면 이상한 우회 경로 |
| B 후보 비교 | `route_mode` 3종으로 후보 3개 → 구간별 안전점수 → 최고 점수 선택 | 단순, 예측 가능, 카카오 경로라 안전 | 세 후보가 거의 같으면 고를 게 없음 (가까운 거리일수록 가능성 큼) |
| C 자체 엔진 | OSM 보행자 도로망 + 안전점수 가중치 다익스트라/A* | 정공법, 등대 취지에 가장 가까움 | 도로망 데이터·알고리즘·응답 속도 전부 직접 해결 |

- **B 기본 + A 보강**: `route_mode` 후보를 구간별 안전점수로 비교하고, 후보가 서로 비슷하거나 최고 점수도 낮으면 A 방식으로 경유지 1~2개를 넣어 후보를 추가한다 (상협 제안을 확정)
- **C는 9주차 MVP 뒤 여유가 있으면 시도** — 조원이 노션에 조사해 둔 다익스트라·A* 자료를 이때 쓴다
- 근거: `route_mode` 비교 실험 (2026-09-29, `docs/route-mode-experiment.md`) — 10쌍 중 3쌍은 후보가 사실상 하나, 나머지도 편안한 길은 넓은 길 우선과 대부분 같아 실질 후보는 2개
- 남은 것: A 보강을 언제 쓸지(겹침·점수 기준)와 경유지를 고르는 규칙. 다른 길이라고 안전점수가 다른지도 아직 모르므로 시설 데이터 적재 후 후보별 안전점수를 보고 정한다
  - 승민 의견 (PR #15 댓글, 2026-10-18): 후보 경로끼리 겹침이 높거나 최고 안전점수가 기준보다 낮으면 경유지 방식을 더하고, 경유지는 기존 후보 경로 근처의 안심시설 밀집 지점 **1~3개**. 위 "B 기본 + A 보강"의 1~2개와 달라 팀 회의에서 개수도 함께 정한다

### 구조 (모노레포 제안)
```
deungdae/
├── CLAUDE.md
├── README.md
├── .gitignore            # node_modules, dist, .env, __pycache__, .ipynb_checkpoints, 원본 대용량 데이터
├── .env.example          # 키 이름만 적고 값은 비움 (KAKAO_REST_API_KEY, KAKAO_JS_KEY, DATABASE_URL, KASI_API_KEY 등)
├── docs/                 # ROADMAP.md, REQUIREMENTS.md, API.md, (ERD)
├── shared/               # types.ts — 프론트·백엔드 공용 타입 (API.md의 공용 타입)
├── apps/
│   ├── web/              # React + Vite (승민)
│   └── api/              # NestJS (상협)
└── data/                 # Python 전처리 노트북·스크립트 (근영). 원본 CSV는 커밋하지 않고 출처·다운로드 방법만 README에
```
- 모노레포를 제안하는 이유: `shared/types.ts`를 프론트·백엔드가 같이 import해야 하고, 3명 팀이라 저장소를 나누면 관리만 늘어난다
- **API 키·DB 접속 정보는 절대 커밋하지 않는다.** `.env`는 `.gitignore`에, 팀 공유는 `.env.example` + 별도 채널

### 브랜치 전략
- `main` 하나 + 기능 브랜치 (`feat/FR-004-shortest-route`, `fix/...`, `docs/...`)
- `main` 직접 push 금지, PR로 합치고 1명 이상 확인 후 merge — **GitHub 룰셋 "main 보호"로 적용 (2026-09-26)**
  - 강제 push·`main` 삭제 금지, PR 필수 + 승인 1명
  - 예외: 저장소 관리자(상협)는 **PR에서만** 승인 없이 merge 가능, 직접 push는 불가. collaborator가 없어 승인해 줄 사람이 없는 동안 작업이 막히지 않게 하려는 것
  - 조원 합류 후 이 예외를 없앨지 팀 회의에서 정하려 했지만 다루지 않기로 함 (2026-10-18 상협). 룰셋은 지금 그대로이고, 바꿀 때는 저장소 Settings → Rules → Rulesets
- 머지된 PR의 브랜치는 GitHub가 자동으로 삭제한다 (저장소 설정 "Automatically delete head branches")
- 커밋 메시지에 요구사항 ID (`FR-004 최단경로 API 구현`)
- 3명 팀이라 `develop` 브랜치는 두지 않는다

## 외부 API 확인 사실 (공식 문서 기준)

### 카카오 도보 경로 `GET https://dapi.kakao.com/v2/routing/walk`
- 카카오디벨로퍼스 API. 심사 없이 사용 가능. 카카오모빌리티 사이트의 "도보 길찾기(제휴 파트너 전용)"는 다른 API — 3주차 발표자료의 "제휴 전용"은 이걸 본 것이므로 수정 필요
- `route_mode`: `BROAD_FIRST`(넓은 길 우선, 기본) / `SHORTEST`(최단) / `ACCESSIBLE`(편안한 길)
- 경유지 `via_x`, `via_y` 최대 5개
- 응답: `route.legs[].steps[]` — 각 step은 거리·안내문구·시간·시작점 좌표와 `path.points`. 좌표는 `[x, y]` = `[경도, 위도]` → 서버에서 `{lat, lng}`로 변환
- 구간별 도로 종류·시설 정보는 주지 않는다
- 에러 상태: `START_LINK_NOT_FOUND`, `END_LINK_NOT_FOUND`, `TOO_MANY_SEARCH_LINK`, `TOO_FAR_AWAY`, `ROUTE_RESULT_NOT_FOUND` 등 — 처리 필요
- 카테고리 검색 `CS2`(편의점), `PM9`(약국)으로 24시 시설 보완 가능 (24시 시설은 2026-10-10 제외해 지금은 쓰지 않음)
- **앱 설정에서 [카카오맵] > [사용 설정] ON 필수.** 꺼져 있으면 403 `NotAuthorizedError` ("disabled OPEN_MAP_AND_LOCAL service") — 2026-09-27 키워드 검색 호출에서 실제 확인. 공식 문서상 카카오맵 REST API 전체에 필요
- 응답의 `landingUrl`은 출발·도착만 담은 카카오맵 링크라 `route_mode`와 관계없이 같다. 모드별 경로를 보여주려면 `path.points`를 직접 그려야 한다

### 카카오 무료 쿼터
- **계정 기준 첫 번째로 활성화한 앱에만 무료.** 테스트용 앱을 새로 만들지 말 것
- 일간: 도보 경로 1,000건 / 지도 Web SDK 300,000건 / 키워드·카테고리 검색 각 100,000건 / 주소↔좌표 100,000건. 월간 전체 3,000,000건
- 초과 시 유료 API 연결하면 도보 경로 건당 10원, 아니면 요청 실패
- B안은 경로 1회에 도보 API 3회 → 하루 약 330회 경로 검색이 상한. 서버 캐싱 필수
- 수치는 변경될 수 있다고 문서에 명시 — 발표 직전 재확인

### 티맵 보행자 경로 (예비) `POST https://apis.openapi.sk.com/tmap/routes/pedestrian`
- `searchOption`: 0 추천 / 4 추천+대로우선 / 10 최단 / 30 최단거리+계단제외
- 경유지 `passList` 최대 5개, 응답 GeoJSON, 구간별 도로 종류(`roadType`)·시설(`facilityType`) 제공
- 무료 요금제 경로안내 일 1,000건, 초과 시 자동 차단
- 티맵 경로를 카카오 지도에 그려도 되는지 약관 미확인 — 교체 시 확인

## 발표 대비 답변

- **왜 카카오인가**: 두 회사를 공식 문서로 비교. 경로 기능과 무료 한도가 같고, 티맵의 차별점인 구간 시설 정보는 안전점수에 쓰지 않아 필요 없었다. 이미 키가 있는 카카오로 결정. 경로 호출은 모듈로 분리해 필요하면 티맵으로 교체 가능
- **카카오 "편안한 길"과 뭐가 다른가**: 편안한 길은 경사·계단 기준, 등대는 야간 안전시설 밀도 기준
- **수익 모델**: 시민 앱은 무료, 누적 안전점수·제보 데이터를 지자체의 가로등·CCTV 설치 우선순위 근거로 제공
